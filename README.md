# 🎲 Газовая трасса — браузерная командная игра

## Что умеет эта версия

- Первый человек, который создаёт комнату, становится её администратором.
- Администратор задаёт название комнаты.
- Администратор выбирает количество команд: от 2 до 12.
- У каждой команды до 4 участников.
- После создания комнаты появляется уникальный код, ссылка и QR-код.
- Игроки подключаются с телефона или компьютера через браузер.
- Каждая команда бросает кубик независимо от остальных.
- Пока одна команда отвечает на вопрос, другая может бросать свой кубик.
- У каждой команды свой незавершённый ход; один вопрос не блокирует остальные команды.
- Администратор управляет началом игры и вопросами.
- Если администратор отключается, права администратора передаются следующему подключённому игроку.
- Вопросы можно добавлять и удалять прямо в браузере.

## 1. Локальный запуск на компьютере

Требуется Node.js 18 или новее.

1. Распакуйте архив.
2. Откройте терминал в папке проекта.
3. Выполните:

```bash
npm install
```

4. После окончания установки выполните:

```bash
npm start
```

5. Откройте в браузере:

```text
http://localhost:3000
```

## 2. Как проверить игру на телефоне в одной Wi-Fi сети

1. Запустите игру на компьютере через `npm start`.
2. Узнайте локальный IPv4 компьютера командой:

```bash
ipconfig
```

3. Найдите строку `IPv4 Address`, например `192.168.1.25`.
4. На телефоне, подключённом к той же Wi-Fi сети, откройте:

```text
http://192.168.1.25:3000
```

5. Если Windows показывает запрос брандмауэра, разрешите Node.js для частной сети.

## 3. Как пользоваться игрой

### Администратор

1. Открывает главную страницу.
2. Вводит название комнаты.
3. Выбирает количество команд.
4. При необходимости меняет названия команд.
5. Нажимает «Создать комнату и стать администратором».
6. Получает код комнаты, ссылку и QR-код.
7. Передаёт QR-код/ссылку участникам.
8. После подключения игроков нажимает «Начать игру».
9. Через раздел «Вопросы» добавляет собственные вопросы.

### Игрок

1. Открывает ссылку или сканирует QR-код.
2. Вводит имя.
3. Выбирает команду.
4. Выбирает свободное место участника 1–4.
5. Нажимает «Присоединиться».
6. Ждёт запуска игры администратором.

## 4. Независимые ходы

У каждой команды отдельное состояние хода.

Например:

- Команда 1 бросила 4 и получила вопрос.
- Команда 2 в этот же момент может бросить 6.
- Команда 3 может отвечать на свой вопрос.
- Команда 4 может ждать своего решения.

Команды не блокируют друг друга.

При этом одна команда не может сделать второй бросок, пока её собственный вопрос или специальная клетка не завершены.

## 5. Важное ограничение текущей версии

Состояние комнат хранится в оперативной памяти сервера. Если сервер перезапустить или приложение будет перезапущено после обновления, существующие комнаты исчезнут и нужно будет создать новую комнату.

Для одного мероприятия это нормально: перед игрой запускайте свежую версию, создавайте комнату и не перезапускайте сервер до окончания игры.

Если в будущем потребуется сохранять комнаты, вопросы и результаты после перезапуска, нужно добавить базу данных.

## 6. Как сделать настоящую интернет-ссылку

Для доступа из разных Wi-Fi сетей проект нужно разместить на хостинге.

Подходящий вариант для тестирования — Render Web Service.

Общая схема:

```text
Ваш компьютер
    ↓
GitHub-репозиторий
    ↓
Render Web Service
    ↓
Публичная HTTPS-ссылка
    ↓
QR-код комнаты
    ↓
Телефоны игроков
```

### Перед публикацией

1. Создайте репозиторий на GitHub.
2. Загрузите в него содержимое этой папки.
3. Не загружайте `node_modules`, если они появились после `npm install`.
4. На Render создайте `New → Web Service`.
5. Подключите GitHub-репозиторий.
6. Для Node.js укажите:

Build Command:

```text
npm install
```

Start Command:

```text
npm start
```

7. После успешного деплоя Render выдаст публичную ссылку вида `https://...onrender.com`.
8. Откройте эту ссылку.
9. Создайте тестовую комнату.
10. Откройте ссылку комнаты на другом телефоне.
11. Проверьте подключение нескольких команд.
12. Проверьте независимые броски кубика.
13. Только после этого передавайте ссылку участникам.

## 7. Что передавать другому человеку

Если человек должен просто играть, ему нужен только URL опубликованной игры или QR-код.

Если человек должен получить сам проект для дальнейшего редактирования, передайте ZIP-архив или доступ к GitHub-репозиторию.

Игрокам не нужны Node.js, npm или архив с проектом — при публикации они используют только браузер.

## 9. Рекомендация

Для первого теста используйте локальный запуск. После успешной проверки разместите проект на хостинге и создайте одну тестовую интернет-комнату. Перед мероприятием не обновляйте сервер во время уже запущенной игры, чтобы не потерять состояние комнаты.
